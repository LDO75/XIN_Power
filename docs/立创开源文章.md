# XIN Power：从低压调试到完整软硬件闭环的 3.2～32V 数控电源

> 基于 PY32F403 与 SC8701 的 V2 补丁硬件项目，支持触摸屏、有线/蓝牙上位机、16点电压校准、过流关断、在线升级，以及小误差区间的 PI 电压微调。本文记录当前方案，也保留开发过程中走过的弯路。

## 一、为什么做这台电源

做单片机和各种小板子时，最常用的功能其实很直接：设定电压、限制异常电流、观察功率，出问题时及时关闭输出。3.3V尤其重要，因为这正是很多单片机的工作电压。

XIN Power的开发经历了多轮固件、上位机和硬件修改。最耗时的问题集中在低压区：3.6V校准时，输出从约3.5V突然跳到4V；部分阻值配置下，2V目标始终降不下来；关闭输出后，还能看到规律性的小幅电压波动。期间尝试过直接DAC映射、连续PID、反馈电阻调整、理想二极管供电修改，以及采样和任务调度优化。

最后根据当前V2板子的实测表现，把公开版本的调压范围确定为 **3.2～32V**，电流设定上限 **8A**。这个取舍保留了3.3V应用所需的低压区，也让软件参数与当前硬件保持一致。

项目在原开源电源方案的基础上继续开发。原项目作者为立创开源用户 **cyxsnbb666**，原工程链接：[Type-C可调电源原项目](https://oshwhub.com/cyxsnbb666/typec-adjustable-power-supply-wi)。感谢原作者提供功率级设计和源码参考。XIN Power的PY32工程、上位机、校准流程及后续补丁在此基础上迭代，第三方器件库和字体保留各自许可声明。

完整源码与版本索引：[LDO75/XIN_Power](https://github.com/LDO75/XIN_Power)。

**8A是设定上限。** 当前代码同时保留4.8A输入过流阈值，因此28V输入时对应约134.4W输入功率，输出还要扣除转换损耗。没有完成32V、8A连续输出的热与功率验证，不能把两个量程端点相乘作为已验证输出功率。

这个版本的“限流”采用过流关断方式，软件没有实现恒流输出。用于需要恒流充电、电子负载或电池管理的场景时，应另行设计相应控制环和保护方案。

## 三、系统结构

系统可以分为功率通路、调压通路、测量通路和交互通路。

```text
输入电源 → SC8701四开关功率级 → 输出测量与端子
                ↑ CE使能              │
                ↑ FB                  ↓
PY32 → MCP4725 → LMV321          输出INA226
  │                                 │
  ├─ 输入INA226、NTC                 │
  ├─ W25Q256校准/设置/升级            │
  ├─ ST7789屏幕、CST836触摸           │
  └─ 有线/蓝牙上位机 ←───────────────┘
```

SC8701负责功率级内部闭环，单片机通过DAC调整反馈网络的工作点。INA226提供外部测量，单片机先判断电流保护，再处理其他控制和交互任务。最新PI属于功率级已有闭环外面的慢速微调环。

SC8701的器件能力可参考[南芯官方资料](https://cn.southchip.com/upload/file/SC8701_datasheet_brief_cn.pdf)。整板可用范围仍由具体反馈网络、器件供电、MOS、布局、热设计和固件共同决定。

## 四、调压公式和校准为什么要分开

反馈节点的直流关系可以先用KCL估算。设上拉电阻为Ru、对地电阻为Rd、DAC注入电阻为Ri，缓冲器输出为Va，正常闭环的FB电压为Vfb，则：

```text
(Vout − Vfb)/Ru + (Va − Vfb)/Ri = Vfb/Rd
Vout = Vfb × (1 + Ru/Rd + Ru/Ri) − Va × Ru/Ri
```

按当前电阻及代码使用的Vfb=1.22V，Vout约为41.10−19.57×Va。DAC以3V、4096码比例估算，每增加一码，输出约降低14.33mV。这解释了两个现象：升高输出电压需要降低DAC码；显示可以按mV给出数值，但物理执行器没有1mV一步的分辨率。

这里的公式假设缓冲器在线性区、FB正常闭环、后级没有额外异常。它适合提供初值和斜率，不能替代实物校准。特别是低压区需要更高的DAC注入电压，还需要核对运放输入共模和输出摆幅。LMV321并不能只凭“输出接近电源轨”这一项就保证所有输入点位正常，可参考[TI官方数据手册](https://www.ti.com/lit/ds/symlink/lmv321.pdf)。

### 当前16点校准

点位按电压升序排列：

**3.2、3.3、3.5、3.8、4.0、4.2、5、7.2、8.4、9、12、18、20、24、28、32V。**

低压区更密，是为了给3.3V附近留下足够的实测信息。高压区变化相对平滑时，采用更稀疏的点位。

流程为：选点 → 手动微调DAC → 等待万用表读数稳定 → 输入实测电压 → 采集并保存 → 读回核对。

每个点独立保存并立即参与映射，不需要全部16点完成后才能使用。正常输出根据已保存的“实测电压—DAC”关系插值。手动校准期间固定人工DAC，PI暂停，避免把正在自动移动的执行器当成固定校准点。

旧表按名义电压迁移，不按旧点位ID直接套用。阻值改动后，旧DAC曲线可能不再适用；更换R316后必须核对硬件标记和校准表。没有可靠实测点的区间也不能被宣称已经精密校准。

## 五、低压问题的完整排查过程

### 1. 校准流程曾经太复杂

早期版本在校准中加入了稳定窗口、漂移门槛、靠近目标才能保存等条件。实际使用时出现“已经调到目标，仍不能采集”的情况。后续回到更直接的方式：人工调DAC，输入万用表实测，保存对应关系。

这次调整明确了校准和保护的职责。校准解决测量及映射关系；越限关断解决异常供电。保存成功还必须由设备确认、Flash写入和读回核对共同证明，单凭上位机按钮变色不够。

### 2. 连续PID没有直接解决所有低压异常

6.0.5～6.0.7尝试持续PID，并增加实时参数和读取接口。调试中还遇到PD电源在长时间小电流时休眠、人工关断影响阶跃记录等情况。这些都会改变试验条件。

更关键的是，输出级异常、供电漂移和反馈电阻不匹配都不是单纯提高或降低PID参数就能修复的。参数整定需要先确认输入稳定、测量可信、执行器工作正常，然后根据阶跃和加载/卸载响应调整。

### 3. R316影响可调范围，也影响旧校准表

把R316从7.5kΩ改为4.99kΩ，改变了DAC对FB的注入增益。软件必须同时修改理论参数和曲线标记。仅换电阻、仍使用旧映射，很容易出现预置DAC码不合适、低压区异常或校准点失准。

当前公开版本固定R316=4.99kΩ。历史7.5kΩ版本仍作为开发记录保存，其固件不适合作为当前补丁板的默认下载版本。

### 4. 理想二极管的供电成为关键线索

实板排查中发现：理想二极管前后的表现不同；SRC从输出侧经原RC供电时，固定DAC下电压会缓慢上升，约一分钟后趋于稳定，需要人工调整至少10码才能抵消。改为输入侧28V直接供电后，用户报告缓慢漂移消失，低压校准也恢复正常。

另一组观察是关闭输出时出现约0.98Hz的周期波动。改变SRC供电方式，波动幅度会变化；断开SRC后该现象消失，前端和后端残压也明显降低。这些结果把排查重点指向输出理想二极管及其与前级的交互。

这些是实板观察，能支持“该级参与了异常”的判断。它们还不足以单独证明MX16171内部某个具体保护状态、某种MOS寄生参数或某个固定阈值就是唯一根因。期间的简化模型用于研究可能的充放电和启停机制，不应写成芯片内部电路已经被准确仿真。

### 5. 最终旁路输出理想二极管

当前板把输出理想二极管MOS的D/S短接旁路，后续软件按这个状态适配。这样避免继续依赖该级的低压工作和供电行为。

这项修改也改变了功能边界：输出端失去这一层防倒灌和隔离能力，软件“关闭输出”控制的是SC8701使能，不能据此承诺端子被物理断开。接外部带电电源或电池、并联其他电源等用途需要重新设计输出隔离，不能沿用原理想二极管的功能描述。

## 六、保护逻辑：先看电流，再处理其他事情

有一次空载低压校准触发SHORT，日志显示电压很低，电流也只有接近零的微小数值。问题出在把“低电压状态”当成独立短路依据。后续去掉这一判断，让短路大电流走同一过流关断路径。

当前软件保护如下：

| 保护 | 当前判定 |
|---|---|
| 输出过流 | 大于用户设定，首个有效越限电流读数关断；8.5A绝对备用阈值 |
| 输入过流 | 大于4.8A，首个有效越限读数关断 |
| 输入欠压 | 小于4V持续200ms |
| 输出绝对过压 | 大于33V |
| 输出相对过压 | 高于参考+max(300mV，参考的10%)持续100ms |
| 过温 | 有效温度达到80℃ |
| 监测失联 | 输出开启时完整新样本持续中断500ms |

故障关断锁存，清除故障后仍保持关闭，需要人工重新开启。手动DAC校准暂停相对过压判断，但绝对过压、电流、温度和监测失联等仍保留。降压过程的过压参考按泄放RC估算下降，避免正常放电被旧目标与新目标的差值误判。

显示电流会扣除板内泄放电流并做零点修正；保护使用扣除泄放前的电流，避免显示修正掩盖真实越限。软件保护依赖INA的转换、I²C读取和调度延迟，不能被描述成微秒级硬件短路比较器。模拟功率级和板上CE相关电路的响应还需分别测量。

## 七、为什么采样500Hz、屏幕50Hz、回传25Hz

曾经把INA轮询提高到1kHz后，实板出现触摸与屏幕刷新失效。最终把三类任务分别确定为：

- 测量与电流判断：目标2ms一次，即500Hz。
- 屏幕刷新：目标20ms一次，即50Hz，主要更新变化区域。
- 常规回传：默认40ms一次，即25Hz。

INA226采用连续母线/分流转换，各332µs、平均1次，只有确认新转换完成才计为新样本。转换时间可参考[TI INA226数据手册](https://www.ti.com/lit/ds/symlink/ina226.pdf)。500Hz是软件调度目标；实际最大样本间隔仍受总线、LCD、Flash等工作影响，需要记录实测。

屏幕分段传输时继续服务采样。串口发送使用DMA，遥测拥塞时丢弃整帧，下一周期发送最新状态，避免旧遥测挤占控制任务。

协议5发送实际二进制字节，采用同步头、类型、长度、序号和CRC16。常规遥测载荷77字节，整帧87字节。25Hz对应2175字节/秒，115200、8N1时约占19%的线速。上位机解包后显示中文状态，不需要用户逐行阅读英文原始报文。

通信还增加了同序号去重，防止命令重试把“DAC步进一步”或“保存一次”执行两次。有线读取异常时尝试恢复同一端口，重连后读取真实状态，不重放之前的开启、调压或校准操作。

此前Windows曾返回串口“拒绝访问”错误。回传频率和恢复逻辑已经修改，但设备、驱动或电气层面的断链根因尚未被唯一定位，因此这里不会把25Hz描述成对所有USB断链的彻底修复。

## 八、设备界面和上位机

主界面保留调压、过流阈值和输出开关。中间栏左侧显示低频波动Vpp，右侧显示功率；移除使用率低的波形页，以及主界面的Ah/Wh累计显示。

Vpp取最近1秒有效电压样本的最大值减最小值，使用未经过显示低通的校准后电压。换目标时暂停并重新建立统计窗口，稳定后再更新，避免把正常升降压过程算作纹波。正常PI的小幅变化仍进入统计，真实波动不会因每次调码而被隐藏。500Hz采样无法代表开关频率纹波，测高频纹波仍需要示波器。

切页时先全屏清黑，再绘制新页面。返回主界面强制重画顶部栏，局部数字刷新恢复一致的背景。用户反馈残影已有明显改善；清黑处理遗漏像素，液晶物理残留或反光则需要另行辨别。

中文设置页提供亮度、蜂鸣器、方向、零点校准、休眠和版本信息。公开发布副本使用OFL授权的思源黑体生成字库，派生位图名为XIN UI Heiti，保留黑体风格。

## 九、6.2.3为什么增加小误差PI

DAC校准映射解决静态工作点，负载变化后仍可能出现小幅压降。6.2.3在整个3.2～32V范围内增加PI微调，但按照本次需求，只有实测误差进入±0.1V后才工作。

```text
正常开启：应用校准映射DAC
误差≤100mV：PI微调
误差>100mV：暂停PI，保持已经应用的DAC
重新进入范围：无突变地恢复积分
手动校准、关闭或故障：停止/重置PI
```

这里的±100mV是**启用条件**，没有被实现成总补偿幅度限制。如果负载造成的压降超过100mV且前级不能自行回到范围，当前控制不会主动追赶。调整Ki无法绕过这一明确的准入规则。

初始参数为Kp=0.20、Ki=2.00/s、Kd=0。每个新样本按实际时间间隔积分；8mV死区、DAC决策滞回、至少10ms写码间隔及单次最多一码，用于抑制测量噪声和12位量化来回跳码。饱和时处理积分，写入失败不把未执行的动作当成已经执行。

把前级响应近似为一阶系统时，可以推导外环的稳定条件，也做了216组不同时间常数、延迟、增益、加载/卸载和噪声组合的模型检查。但实际SC8701轻载模式、额外极点、MOS寄生和布局并未被完整纳入。**这套PI参数仍需实板带载整定**，模型通过不能承诺任何负载都无过冲。需要纯DAC对照时，可阅读历史6.2.2节点。

## 十、版本如何阅读

## 十一、编译、下载与验证

当前完整工程按顺序提供：01_Bootloader、02_Application、03_Factory、04_Recovery、05_PC_Tool。APP基址为0x08008000，Bootloader位于0x08000000起始的32KiB区域。

已有兼容Bootloader的板子只更新APP，保留W25Q256校准数据。空片可分别编译Bootloader和APP，通过工厂脚本生成合并HEX，再用SWD首次安装。仓库给出地址检查、合并步骤和编译入口，不把APP文件误当成完整空片固件。

上位机基于Python、PySide6和pyserial，可从源码运行或按脚本打包。协议、校准、保护、存储和UI已有离线回归检查。公开字体替换后的构建与检查结果单独记录，避免用旧二进制的结果替代新包验证。

实板验收应记录输入条件、目标、负载、DAC、测量电压、保护现场、实际采样间隔及波形。重点包括3.2/3.3V启动、加载/卸载、降压、短路关断时间、长期热状态，以及切页/休眠/通信同时工作时的调度表现。

## 十二、这次开发留下的经验

1. 固定DAC而实测电压继续漂移时，先沿着参考电压、缓冲输出、FB、转换前后节点查硬件，不能直接认定是软件PID。
2. 改一个反馈电阻，也要同步检查理论映射、持久化曲线和硬件版本标记。
3. 校准保存应有写入确认和读回证据；界面上的成功提示必须对应真实设备状态。
4. 短路判据要匹配实际电流和硬件响应，低电压、小噪声本身不能作为短路证据。
5. 采样频率、屏幕频率、遥测频率和控制带宽是不同概念，需要分别设定和测量。
6. 输出保护、输出隔离和防倒灌是不同功能，旁路硬件以后必须更新产品描述。
7. 保留关键历史版本、硬件前提和未验证项，比只发布一个“最终稳定版”更方便后续开发者复现。

下一步重点是实测PI动态、保护关断延迟和功率热边界，以及在下一版PCB中设计明确的输出隔离/泄放方案。当前开源内容把已完成的软件、实际板上修改和仍需验证的部分一起公开，欢迎基于完整记录继续改进。
